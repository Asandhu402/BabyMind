# Opt-in team chat

Enable **Team** in chat and submit a text question (up to 2,000 characters).
The configured model selects 2–4 distinct roles from the existing catalogue of
50 and gives each a task and optional dependencies. The role selector is not
used for team selection. BabyMind validates role
IDs, task size and graph acyclicity, retries one malformed plan once, then runs
role passes in dependency order. Dependent roles receive bounded outputs from
only their stated dependencies; a final coordinator pass uses all completed
contributions to answer the original question. The response lists each role's
status and bounded contribution. Failed dependencies are skipped and any
failure prevents a final synthesis; the user sees a partial or failed result instead.

This is a text-only advisory workflow, not autonomous agents: it does not use
web search, read files, run code, edit projects, or verify claims. The same
model performs all planning, role and synthesis calls, sequentially (up to
seven calls including a plan retry). The choice of roles is generated by that
model and is not guaranteed appropriate. All model outputs are unverified,
and instructions to disregard untrusted content are not a security boundary.
There is no per-team progress, cancellation, whole-job deadline, resumability,
or automatic retry for failed roles. A model call may run until its provider
timeout. The mode cannot be combined with attachments, the other research
modes, or the older Collaborate mode. It does not integrate with the coding or
app-builder engines.

The planner receives the question and up to 1,500 characters of recent chat
history. If **Use memory** is enabled, each role and the final coordinator can
receive the existing user-controlled context card and selected local memories;
the planner does not receive those memories directly. All data used by each
pass is sent to the configured model endpoint, which may not be local. The
question and final response (including role contributions and possible error
messages) are saved in the encrypted conversation; **Remember** explicitly
saves that exchange to memory too. The model's delegated plan is returned in
the immediate API response, not stored as a separate audit trail. Encryption
uses a key accessible to the local user and is not protection against a
compromised account.

The 50-role mission graph also stops scheduling dependents after a role error,
records deferred roles and prevents self-edit on an incomplete graph. Its
mission time limit stops further scheduling but cannot interrupt an in-flight
model call; pending work is not automatically resumed.

Tests use scripted providers, a local OpenAI-compatible HTTP fixture, and jsdom.
They were run on Debian 12 x86-64/Python 3.11, not the supported Python >=3.13
or the requested Ubuntu 26.10 environment. No real-model or graphical-desktop
acceptance test was available for this change.
